# OpenSwitcher Bugfixes Implementation Plan

> **For agentic workers:** dispatch one `subagent` per task (recommended), or execute tasks inline with `todo_write`, one at a time.

**Goal:** Исправить 10 багов и недочётов, найденных при аудите проекта OpenSwitcher.

**Architecture:** Все исправления — хирургические правки в существующих файлах без изменения архитектуры. Самое сложное — рефактор usleep (Task 1): логика симуляции уходит в фоновый поток, флаг isSimulating и сброс буфера выравниваются.

**Tech Stack:** Swift 6, macOS 13+, AppKit, CGEventTap, Carbon TIS, IOHIDManager.

**Spec:** docs/superpowers/plans/2026-11-18-bugfixes.md (этот файл — и план, и спека)

## Global Constraints

- Деплой-таргет: macOS 13+ (Package.swift)
- Swift 6 strict concurrency: все публичные методы EventTapManager, LayoutManager, SoundManager — `@MainActor`
- Не менять публичный интерфейс классов (методы, свойства, имена)
- Не добавлять зависимостей (Package.swift без изменений)

## Review Focus

1. **Быстрый ввод во время симуляции** — pendingEvents должны выстреливать только после полной симуляции, без двойных букв.
2. **Cmd+V сразу после Double Shift** — пользователь не должен видеть конвертированный текст при вставке из буфера.
3. **Toggle "Запуск при входе"** — на macOS 13 должен работать после удаления `#available`.
4. **Несколько языков** — при наличии 3+ раскладок `refreshSources` должен находить EN и RU без лишних вызовов.
5. **Звук включён и сразу выключен** — `play()` должен читать актуальный флаг без обращения к UserDefaults при каждом вызове.

### Task 1: Убрать usleep с главного потока (EventTapManager)

**Files:**
- Modify: `Sources/EventTapManager.swift`

**Interfaces:**
- Produces: приватные методы `autoReplace`, `fixDoubleCaps`, `switchLastWordOrSelection` выполняют I/O на фоновом потоке; флаг `isSimulating` защищает от входящих событий на `@MainActor`.

- [ ] **Step 1: Добавить фоновую очередь-свойство**

В начале класса добавить:
```swift
private let simulationQueue = DispatchQueue(label: "openswitcher.simulation", qos: .userInteractive)
```

- [ ] **Step 2: Перенести блок usleep+sendBackspace+sendString в simulationQueue**

В методе `autoReplace` обернуть тело (от `isSimulating = true` до `flushPendingEvents()`) в `simulationQueue.async { ... }`. Внутри блока:
1. `DispatchQueue.main.sync { isSimulating = true }`
2. `LayoutManager.shared.switchTo(targetLanguage)` — Carbon TIS вызывается через `DispatchQueue.main.sync`
3. `usleep(20_000)` — остаётся, но теперь НЕ блокирует main
4. `sendBackspace(count:)` — остаётся
5. `usleep(20_000)`
6. `sendString(_:)`
7. `DispatchQueue.main.sync { isSimulating = false; flushPendingEvents(); ... обновить lastCompletedWord/lastTrailingDelimiter }`
8. `playSound()` — вызвать через `DispatchQueue.main.async`

Аналогично `fixDoubleCaps` и `switchLastWordOrSelection`.

- [ ] **Step 3: Убрать `DispatchQueue.main.async` из handleKeyDown вокруг autoReplace/fixDoubleCaps**

После переноса в simulationQueue вызовы идут напрямую (без `DispatchQueue.main.async { self?.autoReplace(...) }`), так как тело уже async.

### Task 3: Fix pasteboard race в replaceAccessibilitySelection

**Files:**
- Modify: `Sources/EventTapManager.swift`

**Interfaces:**
- Produces: буфер обмена восстанавливается атомарно через `changeCount`, а не через фиксированный asyncAfter(0.3s)

- [ ] **Step 1: Заменить asyncAfter на changeCount-наблюдатель**

Заменить блок:
```swift
DispatchQueue.main.asyncAfter(deadline: .now() + 0.3) {
    if let old = oldString {
        pasteboard.clearContents()
        pasteboard.setString(old, forType: .string)
    }
}
```

На:
```swift
if let old = oldString {
    let targetCount = pasteboard.changeCount + 1  // после нашей вставки
    DispatchQueue.main.asyncAfter(deadline: .now() + 1.0) { [weak self] in
        // восстанавливаем только если буфер не менялся после нашей вставки
        if pasteboard.changeCount == targetCount {
            pasteboard.clearContents()
            pasteboard.setString(old, forType: .string)
        }
    }
}
```
